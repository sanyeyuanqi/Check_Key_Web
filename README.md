# Check_Key_Web

网页端采用前后端分离架构：

- `frontend/`：Next.js 16 / React 前端，默认端口 `3000`。
- `backend/`：FastAPI 后端，默认端口 `8000`。
- PostgreSQL：持久化账号、会话、密钥及检测批次。
- Redis：登录限流、检测结果消息队列和网页查询缓存。
- `worker`：从 Redis Stream 收集检测结果，达到 1000 条或等待 30 秒时批量写入 PostgreSQL。

## 本地启动

1. 安装 Docker Desktop。
2. 确认 `web/.env` 只保存在本机，不提交源码。
3. 在本目录执行 `docker compose up --build`。
4. 打开 `http://localhost:3000`，后端健康检查为 `http://localhost:8000/health`。

数据库结构由 Alembic 管理。FastAPI 容器启动时会先执行最新迁移。桌面端可通过环境变量
`KEY_CONTROL_API_URL=http://localhost:8000` 上传到本地后端。

## 账号权限与 IP 访问管理

账号分为超级管理员（`super_admin`）、管理员（`admin`）和普通用户（`user`）。超级管理员可生成普通用户和管理员账号、重置其密码、停用或恢复账号；管理员只能生成和管理普通用户，无法操作其他管理员或超级管理员。当前账号及超级管理员账号不能通过账号管理接口重置或停用。停用账号及重置密码都会撤销该账号现有会话，恢复账号不会恢复旧会话。

全新数据库使用 `BOOTSTRAP_ADMIN_USERNAME` 和 `BOOTSTRAP_ADMIN_PASSWORD` 创建超级管理员。已有数据库首次升级时，仅将配置名称对应的已启用管理员提升为超级管理员，保留密码和会话；已有超级管理员时不再提升账号。若找不到匹配的已启用管理员，服务记录警告并保留现状，不会自动提升其他用户。

超级管理员可在“账号管理”的“IP 访问管理”中封禁、解除或重新封禁单个 IPv4/IPv6 地址，并填写备注。记录保存在 `auth_ip_blocks`，解除封禁保留记录。IPv6 压缩形式及 IPv4 映射地址会规范化；不接受域名、IP 网段和通配符。为防止失去管理入口，系统不允许封禁当前请求 IP。

访问限制在后端对所有 `/api/` 接口统一检查，包括登录、已有会话、密钥查询和桌面上传；命中后返回 HTTP 403 和 `IP_BLOCKED`。前端进入页面、恢复焦点及每 30 秒检查访问权限，其他接口命中封禁时也会立即切换为禁止访问页面。`/health` 和 CORS 预检不受封禁影响。IP 来源沿用 Uvicorn 解析后的连接地址，不直接信任客户端提交的 `X-Forwarded-For`；反向代理部署需按下方说明配置可信代理地址。

## 平台密钥存储

密钥按 10 个服务平台存放在独立物理表中：`credentials_openai`、`credentials_anthropic`、`credentials_google`、`credentials_azure`、`credentials_aws`、`credentials_openrouter`、`credentials_tokenrouter`、`credentials_vercel`、`credentials_opencode` 和 `credentials_cloudflare`。OpenCode Zen 使用平台值 `OpenCode`、密钥类型 `opencode_zen`；Cloudflare Workers AI 使用平台值 `Cloudflare`、密钥类型 `cloudflare_workers_ai`，与现有桌面检测器上传格式一致。Cloudflare 上传的完整凭证为 `Account ID|API Token`，加密存储、复制和 TXT 导出均原样保留账号编号及分隔符；通过接口传入的制表符也不会被替换或删除。`credentials` 是按 `provider` 分区的统一查询入口，自身不保存密钥行；历史未知平台保留在 `credentials_other`。按平台或已知密钥类型查询会限定对应平台，由 PostgreSQL 裁剪其余分区。

`credential_registry` 仅登记全局密钥编号、平台、类型和指纹，保留原有类型与指纹的去重规则，不保存密钥内容。检测批次与有效记录关联该全局编号，平台分表不会改变密钥编号或检测历史。新增及重复上传以解析后的密钥类型确定所属平台。

迁移 `20261017_0009` 会在事务中复制既有密文和元数据、核对迁移前后记录、重建关联，并保留编号序列的进度；遇到已知类型与旧平台不一致的数据会中止迁移。有效密钥记录页面默认显示 OpenAI，逐个平台查询，支持单行勾选及本页全选，切换平台、搜索或分页后清空勾选。

## 导出记录

导出弹窗支持同时选择多个密钥状态，所选范围合并为一个 TXT 文件，每行一把密钥，并生成一条导出记录。
状态名称与值由独立的 `credential_statuses` 字典表维护，初始值与检查器一致，例如“权限不足”对应 `permission_error`。
密钥和批次明细的 `status` 保存字典值，并由外键约束；上传新状态时先登记字典，保留其原值，避免被合并为“无效”。
网页筛选、状态名称和多选导出均读取字典；原四类汇总字段保留用于旧检测批次的计数兼容。
左侧“导出记录”展示上线后的密钥导出，按时间倒序分页。管理员可以查看全部记录，普通成员只能查看自己的记录。
顶部支持按操作账号及 IP 地址分别查询或组合查询，提交后回到第一页；重置恢复无筛选列表。账号支持忽略大小写的文字匹配，完整 IP 地址规范化后精确匹配，也支持 IP 前缀；普通成员的查询始终限定在自己的记录内。接口参数为 `GET /api/export-records?username=账号&ip=地址&page=1`。
服务端成功生成 TXT 内容时，会保存操作账号、平台、导出范围、数量、文件名、时间和访问 IP；记录不保存密钥内容。
记录包含零条密钥的导出，不包含校验或解密失败的请求，也不代表浏览器已经保存文件。
历史导出无法补录。记录存储于 PostgreSQL，容器重启后保留；列表接口为 `GET /api/export-records?page=1`。

大量密钥导出使用数据库游标，每批只读取 1000 条密文；服务启动时预热最多 4 个常驻解密进程，按进程数量有界预取并行解密，按查询原序在线程中写入 TXT。读取、解密和写入交错执行，不一次加载所有 ORM 对象或拼接整个文件。下载使用 1 MiB 数据块，减少小块磁盘读取与发送的开销。完整生成后才登记导出记录，再从服务器临时文件分块下载。前端先请求原导出接口的 `prepare=true` 获取少量下载信息，再由浏览器直接下载，避免在网页中构造整个文件的 Blob。原接口不带该参数时仍直接返回 TXT。

下载链接有效期默认 10 分钟，只能使用一次，绑定准备文件的用户及当前登录会话；下载前再次校验登录和 IP 封禁。文件位于服务端私有临时目录，准备失败或取消、下载结束或中断、链接过期及服务正常退出时清理，不进入 Redis；崩溃遗留的带本应用标记且租约过期的目录也会回收。下载始终返回完整文件，不支持同链接断点续传。导出记录表示文件成功生成，不代表浏览器保存成功。

默认同时最多准备 2 份文件、保留最多 16 份文件，单文件最多 512 MiB、临时文件合计最多 1 GiB；超过容量会提示缩小范围或稍后重试。可通过 `EXPORT_BATCH_SIZE`、`EXPORT_MAX_CONCURRENT`、`EXPORT_MAX_PENDING_FILES`、`EXPORT_MAX_FILE_BYTES`、`EXPORT_MAX_TOTAL_BYTES`、`EXPORT_DOWNLOAD_TTL_SECONDS` 调整。`EXPORT_CRYPTO_WORKERS` 默认取 CPU 数与 4 的较小值，可配置 0–8；0 关闭进程池并使用线程解密及一批数据库预取。常驻进程增加固定内存占用以缩短大量密钥解密时间，池故障时安全降级到线程，所有模式均验证密文签名及 UTF-8。当前 Compose 使用单 API 进程，临时文件与下载票据在该进程内管理；重启后未使用的链接失效。扩为多个 API 进程或实例前，需要共享导出存储及票据，或将准备与下载请求路由到同一进程。
新增 IP 字段前的记录显示“—”，不会推测历史 IP。地址取自后端连接信息；使用反向代理时，需将可信代理地址配置到 Uvicorn 的 `FORWARDED_ALLOW_IPS`，由服务端解析来源地址。

“地区”列位于 IP 地址后，读取记录时使用随后端打包的 ip2region IPv4/IPv6 离线库查询国家、省份和城市，已有记录也会显示，无需重新导出。内网地址显示“内网”，本机地址显示“本机”；没有 IP 或无法识别的地区显示“—”。查询不会将访问者 IP 发送到外部服务，地区是 IP 库的归属地信息。离线数据的来源、许可证和更新方式见 `backend/data/ip2region/README.md`。

## 密钥列表查询

平台密钥列表提供两种独立查询：右侧按密钥前缀查询，左侧按状态与上传日期联合查询。非空 `q` 会忽略所选状态和日期，只保留平台、密钥类型及字面前缀条件；空白 `q` 按状态和日期筛选。前缀会去除首尾空格并最多取前 32 位，`%`、`_` 和反斜杠按普通字符匹配。列表和汇总不显示待检测结果。

前缀查询的结果数量及分页按匹配密钥计算；状态目录与汇总保留同平台、同类型的全状态统计，供状态导出使用，不随前缀缩小。状态与日期筛选时，目录和汇总按日期范围统计，选中的状态进一步限定列表。`GET /api/keys` 的日期参数始终要求有效且带时区；前缀模式忽略合法日期的先后关系，筛选模式要求开始时间早于结束时间。

迁移 `20261017_0010` 删除原 `(status, key_prefix, created_at DESC)` 联合索引及附属分区索引，新增 `(status, created_at DESC)` 索引；独立的前缀索引 `(key_prefix varchar_pattern_ops, created_at DESC)` 保留。索引变更在事务内完成，锁等待或执行超时会整体回滚。

## 密钥上传 IP

密钥列表在状态后显示上传请求的来源 IP，批量排队处理时也会保留该地址。重新上传同一密钥后，地址随本次处理结果更新。
上线前未保存来源的密钥显示“—”，不会从节点编号或导出 IP 推测；旧队列消息缺少 IP 时也不会清空已有地址。

## 有效密钥记录

左侧“有效密钥记录”跨平台收录所有曾以 `valid` 状态上传的密钥。相同存储类型的同一密钥只保留一条，重复有效检测更新最近有效时间，后续变为任何其他状态仍保留记录。

右上角“批量导出”下载本页勾选记录；“导出全部”下载当前平台、当前已提交的密钥前缀或 IP 查询下的全部匹配记录，覆盖所有分页。导出保留完整原始凭证，每行一条 TXT，包含曾经有效但当前状态已变化的记录。两个操作都重新检查登录和 IP 权限并写入导出记录；TXT 和解密内容不经过查询缓存。切换平台、查询或分页时取消尚未完成的下载。接口分别为 `POST /api/valid-key-records/batch-export` 和 `GET /api/valid-key-records/export`，批量请求限定 1–100 条本平台归档记录，全部验证成功后才解密。
记录通过 `valid_key_records.credential_id` 关联密钥，展示当前状态、首次有效、最近有效和最近上传 IP；列表返回脱敏内容，完整密钥沿用现有登录后查看/复制操作。
查询方式可切换为密钥前缀或 IP 地址，每次独立查询一种；查询始终保留当前平台及密钥类型范围。接口分别使用 `GET /api/valid-key-records?q=前缀` 或 `?ip=地址`，完整 IPv4/IPv6 规范化后精确匹配，IP 前缀按字面匹配且忽略十六进制字母大小写。直接调用接口同时提供非空 `ip` 与 `q` 时，只按 IP 查询，忽略密钥前缀；空白 IP 不影响原前缀查询。
上线时从当前有效密钥和已保留的历史批次有效结果补录；历史批次没有逐条检测时间，因此补录时间使用批次完成时间（未完成时使用开始时间），无法恢复未保存的历史检测。

## 后台批量写入

检测结果上传统一先加密写入 Redis Stream，成功入队后返回 HTTP 202 和 `queued=true`；`accepted` 表示队列已接收，数据库更新由独立 Worker 进程完成。批次创建仍先写入数据库，上传接口验证批次存在；登录、账号停用、IP 封禁等操作继续实时处理。

默认累计 **1000 条检测结果**立即处理；未达到门槛时，从最早一条结果入队开始最多等待 **30 秒**，有数据即处理，空队列不写数据库。新消息不会推迟截止时间。消息积压时先补满一批再提交，最后不足一批的过期数据直接提交。门槛按结果记录数计算，每个上传分片仍最多 50 条；一条消息可以包含多条结果，消息不会在事务边界拆开。当前部署使用一个独立 Worker 服务。

Worker 将状态登记、密钥更新、有效历史、批次明细和批次计数合并为批量 SQL，一组只提交一次，提交后统一失效查询缓存，再确认并删除已处理消息。重复密钥和批次序号先在组内合并，所有中间有效检测仍保留历史。迁移 `20261017_0015` 给密钥与批次明细增加队列事件编号，重投及旧消息不会覆盖较新的结果或重置其时间。

数据库暂时不可用时，任务留在待处理列表，恢复后重新领取；坏数据任务隔离重试，达到 5 次后将原加密载荷保留到 `key-control:validation-results:dead-letter`，便于人工排查与恢复。日志只记录异常类型及消息编号。队列容量包含待处理和死信消息，默认最多 100000 条消息；满载返回 503 和重试提示，不裁掉未消费数据。Redis 暂时不可用也返回 503，超大上传返回 413。Redis 沿用已有 AOF 持久化，入队确认不代表磁盘故障下的零数据损失保证。

可配置 `QUEUE_BATCH_RECORDS`（默认 1000）、`QUEUE_BATCH_WAIT_SECONDS`（默认 30）、`QUEUE_CLAIM_IDLE_SECONDS`（默认 120）、`QUEUE_READ_MESSAGES`（默认 20）、`QUEUE_RETRY_LIMIT`（默认 5）和 `QUEUE_JOB_MAX_LENGTH`（默认 100000）。Worker 收到停止信号会尝试提交已有缓冲；被强制终止或提交失败的任务保留在 Redis，稍后恢复处理。

## 网页查询缓存

平台列表、有效密钥记录和导出记录复用已有 Redis 的查询缓存，默认保留 10 秒。Docker Compose 默认使用同一 Redis 的逻辑库 1，登录限流与检测队列继续使用原来的逻辑库 0；不新增 Redis 服务，也不改变队列的持久化和淘汰策略。查询参数以摘要生成缓存键，导出记录额外按当前用户及角色隔离。只缓存列表的脱敏元数据，不缓存完整密钥、解密结果、TXT 文件、密码或会话。

状态下拉框的全部数量、逐状态数量和兼容汇总使用独立统计缓存，默认保留 60 秒。统计只按平台、密钥类型与上传日期范围区分，翻页、切换选中状态及密钥前缀查询共享同一份统计。前缀查询继续忽略状态及日期范围。`/api/keys` 与 `/api/credential-statuses` 读取相同的统计缓存，命中后不再执行统计聚合；列表数量仍按实际查询条件计算，日期范围变化不会混用计数。手动刷新会同时重新读取列表和统计。

上传检测结果提交成功后（包括 Worker 处理的结果）立即更新列表、统计和有效记录的缓存版本，生成导出记录后立即更新导出记录的缓存版本。正在处理的旧查询不会写入新版本；旧条目随 TTL 自动到期。每次请求仍先从数据库检查 IP 封禁、账号启用状态和会话有效性，再读取缓存。手动刷新和重复提交相同搜索条件会通过 `refresh=true` 跳过缓存读取。浏览器响应继续使用 `Cache-Control: no-store`，可通过 `X-Data-Cache` 区分 `HIT`、`MISS`、`REFRESH` 和 `BYPASS`。

缓存连接使用复用的连接池和短超时；Redis 异常时查询自动回到 PostgreSQL，并暂时避开故障连接。缓存故障期间的更新无法跨数据库与 Redis 保证原子失效，恢复后旧条目最多保留到其 TTL 到期（列表默认 10 秒、统计默认 60 秒）。单条缓存默认最多 256 KiB，超出则直接返回数据库结果。

可通过 `CACHE_REDIS_URL`、`CACHE_TTL_SECONDS` 和 `CACHE_STATISTICS_TTL_SECONDS`（时长均为 1–300 秒）配置；显式设置空的 `CACHE_REDIS_URL` 可关闭缓存。单独启动后端时默认关闭缓存，启用时填写实际 Redis 地址；使用 Compose 的自定义部署配置时，将同一配置文件同时传给 `--env-file`，例如 `docker compose --env-file .env.deploy -f docker-compose.deploy.yml up -d --build`。
