# Check_Key_Web

网页端采用前后端分离架构：

- `frontend/`：Next.js 16 / React 前端，默认端口 `3000`。
- `backend/`：FastAPI 后端，默认端口 `8000`。
- PostgreSQL：持久化账号、会话、密钥及检测批次。
- Redis：登录限流、节点突发流量计数和检测结果消息队列。
- `worker`：从 Redis Stream 消费高峰期积压的检测结果并写入 PostgreSQL。

## 本地启动

1. 安装 Docker Desktop。
2. 确认 `web/.env` 只保存在本机，不提交源码。
3. 在本目录执行 `docker compose up --build`。
4. 打开 `http://localhost:3000`，后端健康检查为 `http://localhost:8000/health`。

数据库结构由 Alembic 管理。FastAPI 容器启动时会先执行最新迁移。桌面端可通过环境变量
`KEY_CONTROL_API_URL=http://localhost:8000` 上传到本地后端。

## 平台密钥存储

密钥按 10 个服务平台存放在独立物理表中：`credentials_openai`、`credentials_anthropic`、`credentials_google`、`credentials_azure`、`credentials_aws`、`credentials_openrouter`、`credentials_tokenrouter`、`credentials_vercel`、`credentials_opencode` 和 `credentials_cloudflare`。OpenCode Zen 使用平台值 `OpenCode`、密钥类型 `opencode_zen`；Cloudflare Workers AI 使用平台值 `Cloudflare`、密钥类型 `cloudflare_workers_ai`，与现有桌面检测器上传格式一致。Cloudflare 上传的完整凭证为 `Account ID|API Token`，加密存储、复制和 TXT 导出均原样保留账号编号及分隔符；通过接口传入的制表符也不会被替换或删除。`credentials` 是按 `provider` 分区的统一查询入口，自身不保存密钥行；历史未知平台保留在 `credentials_other`。按平台或已知密钥类型查询会限定对应平台，由 PostgreSQL 裁剪其余分区。

`credential_registry` 仅登记全局密钥编号、平台、类型和指纹，保留原有类型与指纹的去重规则，不保存密钥内容。检测批次与有效记录关联该全局编号，平台分表不会改变密钥编号或检测历史。新增及重复上传以解析后的密钥类型确定所属平台。

迁移 `20261017_0009` 会在事务中复制既有密文和元数据、核对迁移前后记录、重建关联，并保留编号序列的进度；遇到已知类型与旧平台不一致的数据会中止迁移。有效密钥记录页面默认显示 OpenAI，逐个平台查询，支持单行勾选及本页全选，切换平台、搜索或分页后清空勾选。

## 导出记录

导出弹窗支持同时选择多个密钥状态，所选范围合并为一个 TXT 文件，每行一把密钥，并生成一条导出记录。
状态名称与值由独立的 `credential_statuses` 字典表维护，初始值与检查器一致，例如“权限不足”对应 `permission_error`。
密钥和批次明细的 `status` 保存字典值，并由外键约束；上传新状态时先登记字典，保留其原值，避免被合并为“无效”。
网页筛选、状态名称和多选导出均读取字典；原四类汇总字段保留用于旧检测批次的计数兼容。
左侧“导出记录”展示上线后的密钥导出，按时间倒序分页。管理员可以查看全部记录，普通成员只能查看自己的记录。
顶部支持按操作账号及 IP 地址分别查询或组合查询，提交后回到第一页；重置恢复无筛选列表。账号支持忽略大小写的文字匹配，完整 IP 地址规范化后精确匹配，也支持 IP 前缀；普通成员的查询始终限定在自己的记录内。接口参数为 `GET /api/export-records?username=账号&ip=地址&page=1`。
服务端成功生成 TXT 内容时，会保存操作账号、平台、导出范围、数量、文件名、时间和访问 IP；记录不保存密钥内容。
记录包含零条密钥的导出，不包含校验或解密失败的请求，也不代表浏览器已经保存文件。
历史导出无法补录。记录存储于 PostgreSQL，容器重启后保留；列表接口为 `GET /api/export-records?page=1`。
新增 IP 字段前的记录显示“—”，不会推测历史 IP。地址取自后端连接信息；使用反向代理时，需将可信代理地址配置到 Uvicorn 的 `FORWARDED_ALLOW_IPS`，由服务端解析来源地址。

“地区”列位于 IP 地址后，读取记录时使用随后端打包的 ip2region IPv4/IPv6 离线库查询国家、省份和城市，已有记录也会显示，无需重新导出。内网地址显示“内网”，本机地址显示“本机”；没有 IP 或无法识别的地区显示“—”。查询不会将访问者 IP 发送到外部服务，地区是 IP 库的归属地信息。离线数据的来源、许可证和更新方式见 `backend/data/ip2region/README.md`。

## 密钥列表查询

平台密钥列表提供两种独立查询：右侧按密钥前缀查询，左侧按状态与上传日期联合查询。非空 `q` 会忽略所选状态和日期，只保留平台、密钥类型及字面前缀条件；空白 `q` 按状态和日期筛选。前缀会去除首尾空格并最多取前 32 位，`%`、`_` 和反斜杠按普通字符匹配。列表和汇总不显示待检测结果。

前缀查询的结果数量及分页按匹配密钥计算；状态目录与汇总保留同平台、同类型的全状态统计，供状态导出使用，不随前缀缩小。状态与日期筛选时，目录和汇总按日期范围统计，选中的状态进一步限定列表。`GET /api/keys` 的日期参数始终要求有效且带时区；前缀模式忽略合法日期的先后关系，筛选模式要求开始时间早于结束时间。

迁移 `20261017_0010` 删除原 `(status, key_prefix, created_at DESC)` 联合索引及附属分区索引，新增 `(status, created_at DESC)` 索引；独立的前缀索引 `(key_prefix varchar_pattern_ops, created_at DESC)` 保留。索引变更在事务内完成，锁等待或执行超时会整体回滚。

## 密钥上传 IP

密钥列表在状态后显示上传请求的来源 IP，批量排队处理时也会保留该地址。重新上传同一密钥后，地址随本次处理结果更新。
上线前未保存来源的密钥显示“—”，不会从节点编号或导出 IP 推测；旧队列消息缺少 IP 时也不会清空已有地址。

## 有效密钥记录

左侧“有效密钥记录”跨平台收录所有曾以 `valid` 状态上传的密钥。相同存储类型的同一密钥只保留一条，重复有效检测更新最近有效时间，后续变为任何其他状态仍保留记录。
记录通过 `valid_key_records.credential_id` 关联密钥，展示当前状态、首次有效、最近有效和最近上传 IP；列表返回脱敏内容，完整密钥沿用现有登录后查看/复制操作。
查询方式可切换为密钥前缀或 IP 地址，每次独立查询一种；查询始终保留当前平台及密钥类型范围。接口分别使用 `GET /api/valid-key-records?q=前缀` 或 `?ip=地址`，完整 IPv4/IPv6 规范化后精确匹配，IP 前缀按字面匹配且忽略十六进制字母大小写。直接调用接口同时提供非空 `ip` 与 `q` 时，只按 IP 查询，忽略密钥前缀；空白 IP 不影响原前缀查询。
上线时从当前有效密钥和已保留的历史批次有效结果补录；历史批次没有逐条检测时间，因此补录时间使用批次完成时间（未完成时使用开始时间），无法恢复未保存的历史检测。

## 突发流量处理

每个桌面节点在短时间内的请求低于阈值时同步写入 PostgreSQL；超过阈值后，请求内容会先加密写入
Redis Stream，由独立 Worker 平滑消费。批次明细以 `(batch_id, item_index)` 保证幂等。
